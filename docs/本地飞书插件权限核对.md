## 已验证发现

1. 插件 `index.ts` 在扩展工厂中直接构造 `ConversationManager`。
2. `conversation-manager.ts` 类字段调用 `ModelRegistry.create(this.authStorage)`。本地实际 SDK 导出的 `ModelRegistry.create` 为 `undefined`，`ModelRuntime.create` 为函数；已用 Node 导入实际 SDK 验证。因此原版初始化存在明确 API 不兼容，安装成功不代表可运行。尚未启动插件完整复现。
3. 创建会话仅传入 `authStorage/modelRegistry` 等旧参数；当前实际 SDK 类型使用 `modelRuntime`，后续适配必须同时迁移初始化和会话参数，不能仅替换一个方法名。
4. 原版会话工厂未传入 `tools/noTools/excludeTools`。不能声称远程会话默认无工具；实际可用集合还取决于默认设置及加载扩展，尚未运行会话枚举。
5. 当前 SDK 支持 `noTools: "all"` 或 `tools: []`；源码将其转换为会话级允许列表。只设置 `noTools: "builtin"` 仍可能允许扩展工具，不足以实现默认关闭全部远程工具。
6. 原版使用 `DefaultResourceLoader` 并执行 `reload/bindExtensions`，扩展本身仍可执行宿主代码。会话工具关闭不是 OS 沙箱，不能宣称阻止所有进程、网络或扩展副作用。
7. 原版还提供历史会话恢复与工作区切换；关闭模型工具不能自动解决历史内容访问、工作区资源加载或入口身份控制。配对与群白名单仍需独立门禁。
